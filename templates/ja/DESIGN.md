# DESIGN.md — レイヤーのデザインルール

room をまたいで共有するものをここに置きます。トークン、コンポーネント、アクセシビリティの
下限です。room はこのファイルから取り、取ったものを `SPEC.md`（`使ってよいもの:` の行）に
書きます。ここにある色・文字サイズ・ボタンを room 側で作り直してはいけません。2つの room が
同じ判断を繰り返すなら、ここへ移して参照します — 両方にコピーしてはいけません。

決めるのはこのファイルで、持つのは2つのファイルです。レイヤーのルートにある `design.css` が
レイヤー自身の CSS で、下のトークンとコンポーネントを一度だけ書き、すべての room が
読み込みます。実際のデザインシステムから描く場合、`vendor/<system>/` にそのファイルを
置きます（固定したパッケージから一度だけコピーし、コミットしたもの）。どちらも room では
なく、手で編集するものでもありません。小さく保ってください。デザインレイヤーは
コンポーネントライブラリではありません。下のトークンは `design.css` の出発点です。
プロジェクト自身のものに一度だけ置き換えます。

## デザインシステム

このレイヤーがどのデザインシステムから描くのか、その正がどこにあるのかを書きます。agent は
マークアップを書く前に何を読むべきかを知れます。

- **正:**（パッケージ、URL、Figma ファイルなど、コンポーネントとトークンの定義がある場所）
- **ベンダリング:**（`vendor/` に固定して置いたコピー。例: `vendor/bootstrap/` の 5.3.8。
  `design.css` だけで描いている間は "none"）
- **MCP:**（agent が Model Context Protocol 経由で読む場合のサーバ名。なければ "none"）

room はベンダリングしたコピーと `design.css` を相対パス（`../../vendor/…`、
`../../design.css`）で読み込みます。そうすれば artifact はディスクから描画されるときも、
`/files/` 配下で配信されるときも同じように解決します。コピーの更新はプロジェクトの
スクリプトが行います — agent ではなく、room ごとでもありません。実装側は同じバージョンを
自分の依存管理で入れます。room は `SPEC.md` に、期待するバージョンを書きます。

MCP サーバの**設定**はここではなく `opencode.json` に書きます。agent はこのディレクトリで
動くので、OpenCode は `modelroom/opencode.json` を読みます。このファイルはどのサーバが
大事かを示すだけです。秘密情報は環境変数に置き、どちらのファイルにも書きません。

## トークン

トークンは CSS カスタムプロパティで、この一式は `design.css` に置きます — room は値のコピーを
持たず、そのファイルを読み込みます。

```css
:root {
  --color-bg: #ffffff;
  --color-fg: #111827;
  --color-muted: #6b7280;
  --color-border: #e5e7eb;
  --color-accent: #2563eb;
  --color-danger: #b91c1c;

  --font: system-ui, -apple-system, sans-serif;
  --text-sm: 0.875rem;
  --text-md: 1rem;
  --text-lg: 1.25rem;
  --text-xl: 1.5rem;

  --space-1: 4px;
  --space-2: 8px;
  --space-3: 16px;
  --space-4: 24px;
  --space-5: 32px;

  --radius: 8px;
}
```

## コンポーネント

2つの room が共有するもの — ボタン、入力欄、バッジ — はここに一度だけ書きます。マークアップ、
状態、使うトークンです。マークアップ自体は `design.css` に置き、room は `SPEC.md` からそれを
参照します。変化が要る room は、その `SPEC.md` にそう書きます。コンポーネントを分岐させず、
ここに書き直しもしません。

## アクセシビリティの下限

- コントラスト: 本文は WCAG AA（4.5:1）、大きい文字と UI は 3:1。
- すべての操作要素は、キーボードだけで到達・操作できる。
- フォーカスを見えるようにする — 代替なしに outline を消さない。
- 指で操作する場所では、タッチ対象は最低 44×44px。

## このファイルではないもの

- room ではありません。1画面だけが必要とする判断は、その room の `SPEC.md` に置きます。
- artifact ではありません。スクリーンショットで見えるものは `index.html` に属します。ここには
  画面を描くためのトークンと、その背景にある理由を置きます。
- `design.css` や `vendor/` ではありません。それらは共有されるファイルそのもので、ここは
  その判断を記録する場所です。`update` はこのファイルに触れません。
